## 10. PowerShell 함정

- `python -c "..."` 안의 따옴표를 PowerShell 이 벗겨낸다. **스크립트 파일로 써서 실행해라.**
- `&&` `||` 없음. `A; if ($?) { B }`.
- `Out-File` 은 BOM 을 붙인다 → 파이썬에서 읽을 땐 `encoding="utf-8-sig"`.
- 한글 출력이 깨지면 `$env:PYTHONIOENCODING="utf-8"`.

## 16. 벤치마킹 — 조회수 터지는 드라마클립 채널 3곳 실측 (2026-09-05)

사용자가 **"포레이로 스타일로 만들고 싶다"** 고 했다. 세 채널을 같은 잣대로 재서 비교한 기록이다.
측정 스크립트는 `forey_probe/` 에 있다 (`geo2.py` 배치·`cuts.py` 컷리듬·`cadence.py` 나레속도·`vtt.py` 자막파싱).
소재 영상은 커밋하지 않는다.

| 채널 | 구독 | 수집 | 총 조회 | 평균 | 구독당 | 길이 | 컷/분 |

| **포레이로** | 18,700 | 10편 | 569만 | 57만 | 305 | 31~44s | **38~45** |

### 16-2. 화면 배치 (1080x1920 환산 실측)

세 채널이 **똑같은 뼈대**를 쓴다. 위 검은 띠에 제목 2행 · 가운데 그림 · 아래 띠.

| | 포레이로 | 무비대장 | 마음 한조각 |
|---|---|---|---|
| 바탕 | 검정 | 검정 | **흰색** |
| 그림 y | **432 ~ 1445** (높이 1013) | 462 ~ 1445 | 500 ~ 1390 |
| 제목 | 2행 · **1행 살구색 / 2행 흰색** | 2행 · **1행 노랑 / 2행 흰색** | 2행 · 검정 |
| 글꼴 | 손글씨 둥근체 | 굵은 고딕(각진) | 굵은 고딕 |
| 아래 띠 | 비움 | **작품 로고**(파스타) | **작품 로고**(신병3) + 상단에 채널 로고·핸들 |
| 대사자막 | 그림 안 아래쪽 · 흰글자 + **두꺼운 검은 테두리** · 손글씨체 | 같음 | 그림 안 · 하늘색/흰색 |

★그림은 16:9 를 **세로로 못 채운다.** 포레이로는 원본을 **좌우로 잘라 1080x1013(약 1.07:1)** 로 만든다.
즉 16:9 원본에서 가운데 1152x1080 만 쓴다. 위아래 검은 띠는 그 결과다.

### 16-3. ★핵심 차이 — 나레이션이 주인이냐 손님이냐

자동자막에서 `»`(화자 전환 = 원본 대사) 개수를 세면 갈린다.

| 채널 | 길이 | 원본대사 `»` | 성격 |
|---|---:|---:|---|
| **포레이로** | 31~42s | **3~6회** | **나레이션이 이야기를 끌고 간다. 드라마는 그림(B롤)일 뿐이다** |
| 무비대장 | 47s | 26회 | 나레이션 + 대사 반반 |
| 마음 한조각 | 66s | **56회** | 나레이션 거의 없음 — 원본 대사 그대로 |

**포레이로를 따라 하려면 여기가 전부다.** 대사를 들려주는 게 아니라 **내가 이야기를 해 주고**,
원본 대사는 한 편에 서너 번, 결정적인 순간에만 튀어나오게 둔다.

### 16-4. 포레이로 나레이션 규격 (3편 실측)

- **길이 31~42초 · 총 260자 안팎** — 세 편이 261 / 260 / 267자로 거의 같다. **초당 6~7자**(보통 낭독보다 빠르다)
- **말 덩이 11~12개 · 2.7~3.8초마다 새 자막.** 자막은 한 번에 **한 줄, 6~15자**만 띄운다
- **★문장을 끝내지 않는다.** 모든 마디가 연결어미로 이어진다:
  `~떨어지고` → `~소각하는데` → `~학살시키고` → `~일본군이었고` → `~태워버리죠` → `~돌아가는데`
  쓰는 어미: **-고 / -는데 / -이었고 / -지만 / -하며 / -자 / -죠**
- **★마지막도 연결어미로 끊는다.** 세 편 다 `~돌아가는데` `~쓰러지는데` 로 끝난다. 결말을 안 준다
- 시점은 **3인칭 해설**. "~하는 일본군이었고", "~감탄하는 가토 중좌" 처럼 **명사로 인물을 지목**한다
- 소리는 **처음부터 끝까지 꽉 찬다.** 무음(-45dB 이하) 비율 **0.0%**, 통합 **-11 LUFS**(우리 기본 -14보다 3dB 크다)

### 16-5. 포레이로 전개 (컷 실측)

```
0.0~3.5초   5컷 난사   ★0초 프레임이 그 편에서 가장 충격적인 그림이다 (시간 순서 무시)
3.5~30초    1.0~2.9초짜리 긴 컷   나레이션 마디와 컷이 같이 넘어간다
마지막 1컷  연결어미로 끊고 끝    "~돌아가는데"
```

- 전체 평균 컷 1.3~1.5초(분당 38~45). 우리 규격 비교: 린박스 36.5 · 리센느 22.4 · 일뽕 11
- ★오프닝 5컷은 **0.4~1.0초**로 짧고, 본문은 **1~3초**로 길다. **앞만 빠르다**

### 16-6. 설명문·해시태그도 다르다

- **포레이로** — 설명문에 **줄거리 3~4줄 + 질문 한 줄**을 쓴다.
  > "…이들이 챙긴 기생 생물 '나진'은 과연 어디로 향했을까요? (일본 본국이 아닌 '조선 경성'의 옹성병원 지하로 이어집니다ㄷㄷ)"
  그리고 `* 작품: 경성크리처` 로 출처를 밝힌다. 태그는 `#작품명 #넷플릭스 #드라마리뷰 #쇼츠`
- **무비대장** — 설명문이 **해시태그 한 줄뿐**(`#흑백요리사2`).
  ★그런데 11,108,377회짜리 「파인다이닝 레스토랑에 갑질하는 미슐랭 기자단」은 **2010년 드라마 「파스타」**다.
  지금 뜨는 작품 태그를 달아 검색·추천을 태운다. **따라 할지는 사용자가 정할 일이다 —
  작품이 설명문과 다르면 시청자 신고·저작권 양쪽에서 위험하다.**

### 16-7. 우리가 따라 할 때 지킬 것

1. **소재 권한.** 세 채널 다 남의 드라마다. §8 대로 사용자에게 확인받고 출처를 표기한다(포레이로처럼 `* 작품:` 한 줄).
2. **나레이션 원고를 먼저 쓴다.** 260자 · 11덩이 · 전부 연결어미 · 마지막도 연결어미. 원고가 곧 편집 설계도다.
3. **0초 프레임을 따로 고른다.** 시간 순서가 아니라 **가장 센 그림**을 맨 앞에 놓는다.
4. 그림은 좌우를 잘라 **1080x1013**, 위 검은 띠에 제목 2행(1행 살구/2행 흰색).
5. 자막은 **한 줄 6~15자**씩만. 나레이션·대사 둘 다 자막을 넣는다.
6. 마스터 **-11 LUFS**, 무음 구간을 만들지 않는다.

### 17-2. 화면 배치 — 10편 전부 똑같다 (1080x1920 환산)


### 17-11. ★싱크 — 이게 0순위다

사용자가 못박은 말: **"제대로, 가장 기본은 씽크 맞추는 거야."**
대본이 좋아도 말과 자막이 어긋나면 그 편은 버린 편이다.

**절차(순서를 바꾸지 마라)**

```
prep → 대사 구간 전사 → dlgcheck → tts → align → build
```

1. 쓸 구간을 잘라 `_asr_sm.py` 로 전사해 **단어 시각**을 받는다.
2. `episode.py` 의 D 블록 자막을 `[(글, 말시작, 말끝), ...]` 로 **단어 시각 그대로** 적는다.
   눈대중 구간은 반드시 어긋난다.
3. `python presets\포레이로\dlgcheck.py <편폴더> <전사.json> <보정초>` 를 돌려
   **"자막 없는 말 0개"** 를 확인하고 나서 굽는다. 보정초 = 전사시각 − 소재시각.

**D 블록은 말이 쉬는 자리에서만 끊는다.**
- 단어 사이가 0.03초밖에 안 비는 자리에서 끊으면, `DLG_TAIL`(0.34초) 자동연장이
  다음 말을 물어 **말이 잘린다.** 사용자가 가장 싫어하는 사고다.
- 앞 덩이 `마지막말끝 + DLG_TAIL < 다음말시작` 이 성립하는 자리만 경계로 쓸 수 있다.
  ep09 에서는 20.06~33.95 가 한 호흡이라 통으로 두고, 0.6초가 비는 33.95→34.55 에서만 끊었다.
- 끊을 자리가 없으면 **통으로 둔다.** 대신 나레 마디를 늘려 비중을 맞춘다.
- 말끝에 붙는 짧은 대답("예", "예 맞습니다")도 **말이다.** 자막을 달거나 블록 밖으로 빼라.
  그냥 두면 dlgcheck 가 잡는다.

**나레 자막은 `align.py` 없이는 못 맞춘다.** 글자수로 나누면 자막이 말보다 앞선다.

**★전사 받아쓰기를 그대로 자막에 베끼지 마라.**
시각은 전사가 정확하지만 **글자는 틀린다.** 소리 나는 대로 받아써 놓기 때문이다.
자막에 넣기 전에 사람이 한 번 읽고 바른 우리말로 고쳐라. 실제로 걸린 것들:

| 전사가 받아쓴 것 | 실제 | 무엇이 틀렸나 |
|---|---|---|
| 저 **대장님**께 | 저 **대대장님**께 | 직책이 깎였다 |
| 장 못 **딴** 겁니까 | 장 못 **담급니까** | 관용구를 잘못 들었다 |
| 남편은 **윤재** | 남편은 **윤윤제** | 성을 잘라먹었다 |
| **까페** / **중년님** | 카페 / (대대장님) | 표기·오인식 |

시각은 건드리지 말고 **글자만** 고친다. 그래야 싱크가 안 깨진다.

### 17-12. 야간 씬 · 장소 튐 (ep10 에서 배운 것)

**야간 씬은 그대로 쓰면 0초 프레임이 죽는다.** 얼굴이 안 보이면 안 눌린다.
`episode.py` 에 **`LIFT = 0~100`** 을 적으면 `build.py` 가 걷어올린다(ep10 은 65).
brightness 만 올리면 화면이 뜬다 — `nightlift()` 는 **감마로 어두운 쪽만** 올린다.

**컷을 다른 장소에서 가져오면 장소가 튄다.**
ep10 소재는 앞 19초가 밝은 실내이고 20초부터가 초소다. 앞쪽 컷을 썼다가
나레는 "밤 초소"인데 화면은 대낮 실내가 나왔다. **먼저 소재를 장면별로 갈라 놓고,
한 편은 한 장소 안에서만 컷을 고른다.** contact sheet 를 먼저 떠서 경계를 찾아라.

- 그 장소 밖에 좋은 대사가 있으면 **대사로 쓰지 말고 나레로 옮겨라.**
  (ep10 의 "끝이 보이는구나" 는 다른 장소라 "군 생활 끝이 보인다던 선임은" 으로 바꿨다.)

**묻고 답하는 사이에는 나레를 끼우지 않는다.** 질문 블록과 대답 블록을 붙여 둔다.
사이가 1초쯤이면 그냥 D 블록 두 개를 연달아 놓으면 된다.

### 17-13. 대사 자막 폭 (ep14 에서 잡은 것)

**대사 덩이는 화면에 적은 그대로 그려진다. 줄바꿈이 없다.**
`WrapStyle: 2` 라 libass 가 자동으로 안 접고, 글자 크기는 짧은 줄 기준으로 잡히기 때문에
**긴 덩이를 하나로 적으면 좌우로 잘려 나간다.** ep14 에서 19자 덩이가 실제로 잘렸다.

- 한 덩이는 **15자 안쪽**으로 적어라. 길면 시각을 쪼개 두 덩이로 나눈다.
- `build.py` 가 덩이마다 실제 잉크 폭을 재서 `CAP_MAXW`(1010px)를 넘으면 경고한다.

**★함정: 재는 판이 좁으면 넘치는 걸 영영 못 잡는다.**
`probe()` 는 1080 폭 판에 그려서 재는데, 1300px 짜리 글은 그 판에서 잘려 1010 으로 측정된다.
그래서 `probe(..., w=4000)` 으로 **넓은 판에 그려** 재야 진짜 폭이 나온다.
(처음에 이걸 몰라서 검사를 넣고도 ep14 를 못 잡았다.)

**★함정 둘: 경고를 늦게 쌓으면 아무도 못 본다.**
`[포레이로 규격 위반]` 칸은 대본 검사 직후에 **한 번만** 찍힌다. 자막 폭은 그보다 한참 뒤,
글자 크기를 정하고 나서야 잴 수 있어서 `WARN.append()` 로 넣으면 **영영 안 찍힌다.**
그래서 폭 경고는 그 자리에서 바로 `print` 한다.
이 두 함정 때문에 ep12·ep14·ep15 에서 잘린 자막을 검사가 세 번이나 그냥 통과시켰다.

**한 덩이 한계는 실측 15자.** 16자부터 1030px 근처가 되어 넘친다.

### 17-14. 컷을 더 넣어도 분당 컷수가 안 오를 때

`("N", "문구", [(a,b), ...])` 의 컷 길이 **합이 그 마디보다 길면 뒤쪽 컷은 그냥 버려진다.**
1초짜리 컷 3개(3.0초)를 2.0초짜리 마디에 넣으면 **두 개만 나가고 하나는 사라진다.**
ep09 에서 컷을 6개 더 넣었는데 분당 컷수가 30.9 → 31.7 밖에 안 올라 한참 헤맸다.

**고쳤다 — 이제 엔진이 컷을 버리지 않는다.** 합이 길든 짧든 **배속만 바꿔** 다 쓴다.
(길면 빨리, 짧으면 느리게. 되풀이는 절대 안 한다.)
그래도 컷을 너무 많이 넣으면 한 컷이 0.3초 아래로 내려가 깜빡인다 — 그때는 경고가 뜬다.

- 눈대중은 **컷 길이 = 마디 길이 ÷ 컷 개수**. 2초 마디에 3컷이면 0.65초씩.
- 이 버그가 살아 있던 동안 ep10·ep11·ep13~ep16 에서 붙이려던 그림이 소리 없이 사라지고 있었다.

**타입캐스트 402 (CREDIT_INSUFFICIENT)** — 스튜디오(웹) 크레딧과 **API 크레딧은 별개다.**
웹에 크레딧이 남아 있어도 API 쪽이 비면 `/v1/text-to-speech` 만 402 로 막힌다.
`/v1/voices` 는 200 으로 잘 돌아오니 **키 문제와 헷갈리지 마라.** 잔액 조회 API 는 없다.
확인은 https://typecast.ai/developers/api 에서 한다.

### 17-15. 나레 밑에 깔 컷은 굽기 전에 **한 장에 모아 눈으로 훑어라**

```
python presets\포레이로\cutsheet.py <편폴더>     →  <편폴더>/cutsheet.jpg
```

나레 컷은 소재 아무 데서나 가져오기 때문에, **그 편 이야기와 상관없는 장면**이 섞여도
완성본을 처음부터 끝까지 보기 전에는 모른다. 실제로 걸린 것들:

- **ep16**: 행정병이 파일을 머리 위로 치켜드는 장면이 들어가 "때릴 듯이 손 올린다"는 지적을 받았다.
  사진 이야기와 아무 상관없는 몸동작이었다.
- **ep15**: 길에 누운 **고양이 한 컷**을 0.7초씩 네 조각으로 갈라 네 마디에 나눠 썼더니
  영상 내내 고양이가 네 번 나왔다. **한 shot 을 조각내면 조각마다 다른 마디에 두지 마라.**
- **ep16**: 문 앞을 지나는 **모션블러 프레임**이 그대로 컷이 됐다.

**컷 고를 때 지킬 것**
1. 그 편 이야기 안에서만 고른다. 다른 사건·다른 장소는 아무리 그림이 좋아도 안 쓴다.
2. **한 마디의 컷은 전부 같은 국면(장소·시점)에서 고른다.** 실내 이야기를 하는 마디에
   야외 그림을 섞지 마라. 그리고 **국면 순서대로** 간다(실내 → 이동 → 현장).
   ep03 에서 "실내인데 야외 영상이 섞인다"고 지적받았다.
3. **특정 장면 전용 그림은 그 마디에만.** ep02 의 손 맞잡는·손가락 약속 그림은
   망상 마디에만 쓴다. 딴 마디에 깔면 "왜 손이 또 나와" 소리를 듣는다.
4. **손·팔을 치켜드는 동작**은 맥락 없이 보면 때리는 것처럼 보인다. 피해라.
5. 같은 shot 을 조각내 여러 마디에 뿌리지 마라. 되풀이로 보인다.
6. 모션블러·초점 나간 프레임은 컷 가운데 시각을 옮겨 피한다. **0초 프레임은 특히.**

**고르는 방법 (이렇게 안 하면 또 섞인다)**
소재를 1~1.5초 간격으로 통째로 떠서 **국면 지도**를 만든다.
어느 구간이 실내·이동·현장인지 적어 두고, 마디마다 그 국면에서만 뽑는다.
`cutsheet.py` 는 **다 고른 뒤 확인용**이지, 고르는 도구가 아니다.

### 17-17. **말하는 사람이 화면 안에 들어와야 한다** — `reframe.py` (2026-09-07)

> 사용자: "말할 때 그 화자가 얼굴 보이게 만들어. 너무 얼빡 안 해도 되고
> 화면에 두 사람이 나올 수도 있잖아. **화면 안에 잘 배치해봐**"
> 사용자: "글자 없고 화면에 사람이 없는 씬도 수정"

**왜 생기나.** 16:9 원본(1920)에서 **가운데 1150px 만** 잘라 세로로 세운다(§17-2).
그래서 x<385 나 x>1535 에 선 사람은 **얼굴이 통째로 날아간다.** 넓은 shot 은
사람이 콩알만 해져서 "말하는 사람이 안 보인다"가 된다.

**고치는 법 — 편마다 한 번 돌린다.**

```
python presets\포레이로
eframe.py <편폴더>      # → <편폴더>/reframe.json
python presets\포레이로uild.py    <편폴더>      # build 가 그 파일을 읽는다
```

`reframe.py` 는 **그 편이 실제로 쓰는 소재 구간만** shot 단위로 훑어 얼굴(yunet)을 찾고,
얼굴이 다 들어오면서 너무 작지도 않은 크롭을 구간마다 계산한다.

| 값 | 뜻 |
|---|---|
| 얼굴폭 목표 | 크롭폭의 **20%** — 얼빡이 아니고 표정은 읽히는 크기 |
| 담는 범위 | 살아남은 얼굴 전부 + 양옆 얼굴 반쪽씩 여백 (두 사람이 같이 나와도 된다) |
| 세로 | 눈높이가 화면 **위 40%** 에 오게 |
| 크롭폭 하한 | 기본의 **0.60배** — 더 좁게 자르면 1080 으로 늘릴 때 뭉갠다 |
| 크롭폭 상한 | 기본 크롭폭(=원본 세로가 꽉 찬 상태). **넓게는 못 간다** |
| 안 건드리는 조건 | 얼굴이 이미 크롭 안에 다 들어오고(±2%) 얼굴폭이 11.5% 이상 |

**★함정 세 가지 (전부 실제로 밟았다).**

1. **벽에 붙은 사진·배경 사람을 얼굴로 잡는다.** 버디연 0.8~1.5초에서 54px 짜리
   벽 사진에 끌려가 **주인공이 화면 밖으로 밀려났다.** → 샘플 프레임의 **절반 이상**에서
   잡힌 얼굴만 믿고, 얼굴폭이 크롭폭의 **5% 아래면 아예 손대지 않는다.**
2. **대사 블록은 한 덩이라 shot 마다 다르게 잡을 수 없었다.** → `build.py` 가
   D 블록의 **그림만** shot 경계에서 쪼갠다(`rsegs`). 소리는 잇달아 이어 붙으니 그대로다.
   **분당 컷수·효과음 자리는 쪼개기 전 `segs` 로 센다** — 안 그러면 컷수가 허수로 뛴다.
3. **한글 경로면 OpenCV 가 yunet.onnx 를 못 읽는다.** `C:/vol_models/` 로 복사해 쓴다(§18-4).

**손으로 덮어쓰기.** 자동이 틀리면 `episode.py` 에 적는다 — **이쪽이 더 세다.**

```python
CROP_SHOT = [(소재시작, 소재끝, 중심x, 중심y, 폭배율), ...]   # 원본 픽셀 · 1.0 = 기본 크롭폭
LIFT_AT   = [(소재시작, 소재끝, 세기), ...]                    # 어두운 shot 만 걷어올린다
```

**★"화면에 사람이 없는 씬"은 크롭으로 못 고친다.** 원본이 캄캄하거나 아무도 없으면
**그 컷을 버리고 다른 컷을 골라라.** 버디연 14.4~18.8초(캄캄한 관물대)가 그랬다 —
나레 컷에서는 빼고, 대사라서 피할 수 없는 16.87~18.77 만 `LIFT_AT` 로 걷어올렸다.

### 17-18. 굽기 전에 build.py 가 막는 두 가지 — 물음표 · 컷 자리 (2026-09-07)

> "내가 글자 물음표 필요한데 넣으라고 했잖아. 내가 말한 거 다 메모하고 박으라고 했는데
> 왜 그게 반영이 안 돼?"
> "5번 말년수능 여기에서 왜 자꾸 장면 중에 다른 장면이 들어가니"

**둘 다 지침서에는 적혀 있었는데 엔진이 검사를 안 했다.** 그래서 매번 새는 것이었다.
글자를 몰래 고치지는 않는다 — **어디가 틀렸는지 짚어 주고 사람이 고친다.**

**① 물음표** — `습니까·ㅂ니까·십니까·겁니까·나요·가요·까요·을까·ㄹ까·냐` 로 끝나는데
`?` 가 없으면 **규격 위반**. 의문사(뭐·뭔·무슨·왜·어디·언제·누구·누가·어떻게·어떤·몇)가
들어 있거나 `나·니·래·데·지` 로 끝나면 "봐야 할 곳"으로 한 줄 찍어 준다.
`니까` 를 무조건 물음으로 보면 **"말하기 싫다니까"** 같은 게 걸리므로 `ㅂ니까` 로 좁혔다.

**② 나레 컷 자리** — 나레 마디의 컷은 **앞 대사가 시작한 곳 ~ 뒤 대사가 끝나는 곳**
(여유 ±3초) 안에 있어야 한다. 0초 프레임만 예외(§17-9).
좁게(앞 대사 끝 ~ 뒤 대사 시작) 잡았더니 **"나레로 먼저 알리고 대사로 터뜨리는"
멀쩡한 배치까지 걸려서** 넓혔다.

**★자리가 모자랄 때 하지 말아야 할 것.** 다른 데서 그림을 빌려 오면 딱 그게
"다른 장면이 끼어든다"가 된다. **문구를 줄이거나 그 마디를 대사 뒤로 옮겨라.**
s2ep5 "그래도 후임들은 돕겠다고 합니다"는 앞뒤 대사 사이가 **0.18초**뿐이라
대사 뒤로 옮기고 "후임들이 돕겠답니다"로 줄였다.

**★문구를 줄이면 나레 비중·글자수가 규격 아래로 떨어진다.** 여유가 있는 다른 마디를
늘려서 채워라(s2ep5 는 n8·n9 를 늘려 116자 45% 로 맞췄다).
한 마디의 나레 길이는 **그 마디 컷 합계 x MAX_STRETCH(1.8) - NARR_PAD** 를 넘으면 안 된다 —
넘으면 그림이 소리보다 짧아져 **싱크가 밀린다.**

### 17-19. 효과자막은 **마디에 걸어라** — 초를 손으로 세지 마라 (2026-09-07)

> "효과자막이 영상이랑 안 맞아. 그렇게 안 맞게 할 거면 차라리 없애버려. 다시 분석해봐"

**무엇이 잘못됐나.** 경성크리처 4편에서 효과자막 자리를 **완성본 초로 눈대중해 적었다.**
나레 길이는 TTS 가 정하고 대사 길이는 원본이 정하므로, 굽기 전에는 알 수 없는 값이다.
결과:

| 증상 | 실제 |
|---|---|
| **영상 밖으로 나갔다** | gs1 "네 인생을 살거라"(54.5초)·gs2 "그런 날이 꼭"(54.2초) — 영상이 50.9·53.9초라 **아예 안 보임** |
| **엉뚱한 얼굴에 붙었다** | gs1 "내 아내요"가 **딸 얼굴** 위에. 아버지가 아내 얘기를 한 건데 |
| **지나간 말이 다시 떴다** | gs3 "동료의 이름을"이 "구차하더라도 살아남아야 하니까" 자막 위에 |
| **두 줄로 접혔다** | "기억해 주지 않을 테니까"(12자)·"쓰레기라고 말하지 마"(11자) — `wrap(txt, 10)` |

**고친 방법 — `episode.py` 에서 마디에 건다.**

```python
EFFECTS = [
    (("D", 3, 0.15), "내 아내요", "left"),    # 3번째 대사 블록이 끝나고 0.15초 뒤
    (("N", 2, 0.10), "그래서요?",  "right"),   # 2번째 나레 마디가 시작하고 0.10초 뒤
    (32.8,           "옛 방식",     "right"),   # 완성본 초 — 받기는 하지만 쓰지 마라
]
```

`build.py` 가 `rows` 를 다 세운 뒤 초로 바꾼다. 그래서 나레 길이가 바뀌어도 **자리가 안 밀린다.**

**★"대사 블록이 끝나고 0.15초"가 왜 맞는 자리인가.** 그 자리는 곧 **그 말에 대한 반응 컷**이다.
§17-16(효과자막은 말이 끝난 직후) 과 "화자가 화면에 있어야 한다"(§17-17)를 동시에 만족한다.

**새로 막는 것 (규격 위반).**

1. 효과자막 + 유지시간이 **영상 밖**으로 나가면 위반.
2. **10자를 넘으면** 위반 — `wrap(txt, 10)` 이라 두 줄로 접힌다.
3. (기존) 그 말이 나오기 **전에** 뜨면 위반(§17-16).

**그리고 굽을 때마다 어디 떨어지는지 찍어 준다.**

```
효과자막 '내 아내요'  27.29초 → 소재  41.16초 (나레)
효과자막 '맞다 카고'  20.87초 → 소재  56.58초 (나레)
```

소재 시각이 나오므로 **국면 지도와 대조하면 굽기 전에 어긋남을 잡을 수 있다.**

### 17-20. 나레는 **대사를 따라 하는 게 아니라 이야기를 몰아가는 것** (2026-09-09)

> "경성크리처 나레이션이 대사를 따라하냐 나레이션이 이야기를 몰아가야지
> 포레이로 나레이션 전개방식 기억하고 하는 거니. 그리고 주인공 이름도 안 맞고.
> 경성크리처 다 다시 분석해. 씽크 안 맞아. 그리고 나레이션도 좀 수정해"

경성크리처 9편이 세 가지를 한꺼번에 어겼다. **셋 다 검사로 박았다.**

**① 나레가 대사를 그대로 되풀이했다.**

| 나레 | 바로 옆 대사 |
|---|---|
| "건물을 무너뜨리지는 못한다고 했습니다" | "건물을 무너뜨리지는 못해도" |
| "친구 이름을 팔아 목숨을 구걸했다고 했습니다" | "친구 이름 팔고 … 내 목숨을 구걸했었다" |
| "도리를 아는 게 사람이라는 겁니다" | "그런 도리는 구분할 줄 아는 게 그게 사람이지" |
| "그 아래에 그의 아내가 있었습니다" | "저 아래 있는 건 내 아내잖소" |

→ `build.py` 가 나레와 **앞뒤 대사의 2글자 겹침이 34% 이상**이면 규격 위반.
**나레는 대사가 말하지 않는 것만 말한다** — 때·곳·관계·이름·앞뒤 사정·결과.
바꾼 예: "건물을 무너뜨리지는 못한다고 했습니다" → **"혼자 들어가 옹성병원을 무너뜨릴 셈이었습니다"**
(대사에 없는 '혼자'와 '목표'를 나레가 준다).

**② 인물을 이름으로 안 불렀다.** "남자·여자·노인"으로만 썼고, g25 는 따지는 사람을
"구 사장"이라 했는데 **화면은 나월댁**이었다.
→ **장태상·윤채옥·나월댁·마에다 유키코**로 박고, 화면과 대조해 확인한다.

**③ 흐린 말을 앞 자막으로 오래 덮어 밀린 것처럼 보였다.**
g25 는 **2.2초**, gs4 는 **1.7초**, gs1 은 **3.5초**(말 사이 침묵) 동안 지나간 자막이 남아 있었다.
→ `build.py` 가 **3.2초 넘게 떠 있는 대사 자막**을 규격 위반으로 막는다.
고치는 법은 둘뿐이다 — **말 사이 침묵이면 자막을 둘로 쪼갠다**(gs1·gs2),
**흐린 말이면 그 자리를 블록에서 뺀다**(g25).

### 17-21. ★★씽크가 컷마다 쌓여 밀린다 — 프레임 격자에 못 박아라 (2026-09-09)

> "씽크 안 맞아. 내가 씽크는 기본 고정을 박아놓고 무조건 맞아야 한다고 했잖아"

**재서 확인했다.** `presets/포레이로/synccheck.py` 로 원본 소리 크기 곡선(20ms RMS)을
완성본에서 찾아 어긋난 초를 쟀다. sb5(35컷) 결과:

| 대사 블록 | 어긋남 |
|---|---|
| 1번째 | +0.04초 |
| 2번째 | +0.08초 |
| 3번째 | +0.14초 |
| 4번째 | +0.20초 |
| 5번째 | **+0.24초** |

**한 번 밀린 게 아니라 컷마다 쌓인다.**

**원인.** 소재가 30fps 인데 `trim=start=S:end=E` 는 **프레임 경계로 올림**된다.
컷 하나에 최대 1/30초(33ms)씩 길어지고, 35컷이면 0.3초가 된다.
자막과 나레는 **계산상 시각**에 놓이므로 그만큼 어긋난다.

**고친 것.**

1. `build.py` 가 소재 fps 를 재고, **모든 마디·컷 길이를 `qd()` 로 1/FPS 격자에 맞춘다.**
   나레 마디, 대사 블록, 나레 컷, shot 쪼개기, 끝 꼬리 자르기까지 전부.
2. 굽을 때 컷마다 **프레임 수로 못 박는다** —
   `fps={FPS},tpad=stop_mode=clone:stop_duration=1,trim=end_frame={nfr},setpts=PTS-STARTPTS`
   소리도 `apad=pad_dur=1,atrim=end={nfr/FPS}` 로 같은 길이에 맞춘다.
3. 결과: 어긋남 **±0.24초 → ±0.02초**.

**★함정 하나 더.** 필터가 길어져 윈도 명령줄 한도(32KB)를 넘었다.
→ 필터를 `_fc1.txt`·`_fc2.txt` 에 쓰고 **`-/filter_complex <파일>`** 로 넘긴다.
(ffmpeg 9 에는 `-filter_complex_script` 가 **없다.**)

**★이 고침 전에 구운 편은 전부 다시 구워야 한다.**

### 17-22. 효과자막 — 블록 **안쪽**에 걸고, 톤이 안 맞으면 뺀다 (2026-09-09)

> "내가 몇 번 얘기했어 씽크 나레이션을 기본이라고.
>  거기에 양념자막을 할 거면 제대로 하고 안 되면 하지 마"

경성크리처 9편 효과자막 27장을 전부 프레임으로 확인했다. 실제로 이랬다.

| 편 | 무엇이 잘못됐나 |
|---|---|
| g25 | **두 장이 같은 순간(32.85초)에 함께** 떴다 — 앵커를 둘 다 D6 에 걸었다 |
| g24 | "꼭 성공하세요"(동지들 대사)가 **나월댁 얼굴** 위에 |
| g22 | "니가 애국자다"가 뜰 때 나레가 "장태상은 그 애국자 소리를…" — **같은 말이 두 번** |
| gs4 | "맞다 카고"가 **얼굴 없는 조명 컷** 위에 |
| 대부분 | 대사가 끝난 **뒤 나레 구간**에 떨어져 말한 사람이 화면에 없다 |

**뿌리 원인.** 앵커를 `("D", n, dt)` = **블록이 끝난 뒤**로 걸었다.
그 자리는 거의 항상 **다음 나레 마디**다. 말한 사람은 이미 화면에서 사라졌다.

**고친 것.**

1. 새 앵커 `("C", n, k, dt)` — **n번째 대사 블록의 k번째 자막이 끝나고** dt초 뒤.
   블록 **안쪽**이라 말한 사람이 아직 화면에 있다.
2. **두 장이 겹치면 규격 위반.**
3. **0장을 허용한다.** "제대로 못 붙일 바엔 빼라"가 지시다. 1장만은 여전히 위반.

**★그리고 뺐다.** 경성크리처는 시대극·비극이다. 분홍 양념자막은 코미디(신병) 것이다.
자리를 고칠 수는 있어도 **톤이 안 맞으면 붙이지 않는 게 맞다.** 9편 전부 `EFFECTS = []`.

### 17-23. ★★나레 자막이 엉뚱한 데 붙던 진짜 원인 — `align.py` 가 **옛 전사를 계속 썼다** (2026-09-12)

> "경성크리처 다시 확인해 씽크 안 맞아"

씽크가 맞는다고 세 번 답했는데 사용자는 계속 안 맞는다고 했다. **사용자가 맞았다.**
내가 잰 것(`synccheck.py`)은 **대사 블록의 그림과 소리**였고, 사용자가 본 것은
**나레 자막 덩이가 목소리와 같이 넘어가느냐**였다. 재는 자리가 달랐다.

**뿌리 원인 — 한 줄.**
`align.py` 가 `if not os.path.exists(asr):` 로만 전사를 건너뛰어서,
**나레를 고치고 TTS 를 다시 만들어도 시각은 옛 문구 기준**이었다.
`gs2/narr/_all.asr.json` 에는 아직 「경성의 전당포에서 약속 하나가 오갑니다」가 들어 있었고,
새 나레는 「금옥당 대주 장태상이…」였다. **19덩이 중 9덩이가 시각을 못 찾았고**,
나머지도 남의 자리에 붙었다. 그 위에 얹은 MINBIT 보정이 그걸 그럴듯하게 밀어 놓아서
"위반 0" 으로 통과해 버렸다.

**고친 것 — `align.py`.**

1. **도장(stamp) 으로 캐시를 깬다.** 나레 원문 + wav 크기·수정시각을 sha1 로 찍어
   `narr/_all.asr.stamp` 에 둔다. 다르면 `_all.asr.json` 을 **지우고 다시 전사**한다.
   ```python
   _stamp = hashlib.sha1((_join + "|" + _sig).encode("utf-8")).hexdigest()
   if _old != _stamp and os.path.exists(asr):
       os.remove(asr); print("  ★나레가 바뀌었다 — 전사를 다시 한다")
   ```
2. **글자 맞춤으로 바꿨다.** 예전엔 "덩이 글자수만큼 단어를 앞에서 꺼내 쓰는" 탐욕 배분이라
   한 번 어긋나면 **뒤가 전부 밀리고 단어 풀이 먼저 바닥났다.**
   이제 쓴 글자열 `T` 와 ASR 글자열 `A` 를 `difflib.SequenceMatcher` 로 맞춰
   덩이→단어 색인을 만든다. 못 맞춘 덩이는 **앞뒤 닻 사이를 글자수 비례로** 채운다.
   → 경성크리처 9편 177덩이 **전부 시각을 찾았다**(이전 gs2 는 10/19).
3. **말이 되는 길이인지 본다.** `MINRATE = 11.0` 자/초 — 그보다 빠르면 늘리고,
   마디를 넘치면 마디 안으로 눌러 넣는다. (「나온 말이었습니다」 0.21초 → 1.57초)

**교훈 두 개.**

- **캐시는 입력이 바뀌면 반드시 깨야 한다.** "파일이 있으면 건너뛴다"는 조용히 틀린다.
- **사용자가 세 번 같은 말을 하면 내 측정 자리가 틀린 것이다.** 재는 곳을 바꿔서 다시 재라.
  (여기서는 완성본에서 덩이 한가운데 프레임을 떠서 **자막 글자를 눈으로** 확인했다)

### 17-24. 자막은 **들리는 대로** — 호칭과 종결어미를 한 귀로 믿지 마라 (2026-09-12)

> "장태주라고도 하고 장태상이라고도 하는데 영상에 사람은 장태주라고 하는데 글은 장태상이라고 해"
> "나도포기하지않을거요 이거 아니야?" / "했소 이렇게 말하는데"

스피치매틱스 하나만 믿고 자막을 적었다가 **두 가지가 통째로 틀려 있었다.**

**① 호칭을 이름으로 바꿔 적었다.**
사람들이 부르는 것은 이름 「장태상」이 아니라 직함 **「장 대주」**(금옥당 대주)다.
스피치매틱스가 이걸 `장대주 / 장태주 / 상대주 / 장례주` 로 흩어 놓으니
내가 "오타겠지" 하고 전부 **장태상으로 고쳐** 버렸다. 화면에서 나는 소리와 글자가 어긋난다.
→ **이름은 나레에서만 쓴다. 자막은 부르는 말 그대로.**

**② 하오체를 반말로 떨어뜨렸다.**
경성크리처 인물들은 `~소 / ~오 / ~요`(하오체)로 말한다. 스피치매틱스는 이걸
`~야 / ~어`로 받아 적는다. 그래서 이렇게 나갔다.

| 쓴 자막 | 실제 말 |
|---|---|
| 나도 당신을 포기하지 않을 거**야** | 않을 거**요** |
| 이미 한번 죽은 몸이**야** | 몸이**오** |
| 그 좋은 시절이 오겠**어**? | 오겠**소**? |
| 올 거**야** / 꼭 오게 할 거**야** | 올 거**요** / 할 거**요** |
| 뒤에는 내가 막겠**어** | 뒤는 내가 맡겠**소** |
| 56미터 정도 | **오륙 미터** 정도 |

**고친 방법 — 두 번째 귀를 댄다.**
`~/.volcano/keys/gemini` 로 소재 오디오를 통째로 다시 받아 적고 **다수결**로 정한다.
모델을 두셋 돌려서 갈리면 원래 것을 둔다(3:0·2:1 만 고친다).

```python
u = "https://generativelanguage.googleapis.com/v1beta/models/%s:generateContent?key=%s"
# gemini-3.7-flash / 3.6-flash / 3.5-flash  (3.5-transcribe 는 빈 응답이 온다)
P = ("1945년 경성 배경 한국어 드라마다. 들리는 그대로 받아 적어라.\n"
     "★종결어미를 정확히 — 하오체(~소/~오/~요)인지 반말(~야/~어)인지.\n"
     "★사람을 부르는 말이 이름인지 직함('장 대주')인지도 정확히.")
```

★**시대극·사극은 이 검사를 반드시 한 번 돌려라.** 하오체·사투리·직함은 한 귀로는 못 잡는다.

### 17-28. ★★대사가 **일본어**인 구간 — 시각은 일본어 전사로, 글자는 **화면 하드섭**에서 (2026-09-13)

평소처럼 `_asr_sm.py src.mp4 asr.json ko` 로 받으면 **통째로 깨진다** —
「すべて焼却」이 "스베테 쇼카쿠"로, 「時間ありません」이 "장 아리마센"으로 음차돼 나온다.
그 글자를 믿고 자막을 짜면 편 전체가 무너진다.

**고치는 법 — 지침서 §8("시각은 믿되 글자는 믿지 마라")을 그대로 밀고 나간다.**

```
python scripts/_asr_sm.py <편폴더>/src.mp4 <편폴더>/asr_ja.json ja   # ★시각만 쓴다
```

1. **일본어로 전사해 낱말 시각을 받는다.** 일본어로 돌리면 시각이 정확하다.
2. **글자는 화면에 박힌 공식 한국어 자막에서 읽는다.** 하드섭 띠만 오려 세로로 쌓아
   한 장으로 보면 빠르다:
   `ffmpeg -ss <t> -i src.mp4 -frames:v 1 -vf "crop=1920:160:0:920" f.png`
3. `dlgcheck` 는 **일본어 전사로 돌려도 된다.** "자막 없는 말"은 **시각 덮임**을 보는 검사라
   글자가 일본어여도 0개를 확인할 수 있다.

★**하드섭이 있다고 소재를 버리지 마라.** `prep.py` 가 `HARDSUB_TOP` 을 잡고
  `spec.crop_filter` 가 그 아래를 잘라낸다(이 편은 y931 → 크롭 990x930).
  신병4 「계급규칙」을 하드섭 때문에 버렸는데, **그럴 필요가 없었다.**

★`drawtext` 로 국면 지도에 초를 박으려다 또 죽었다(§7 함정). **타일만 쓰고 초는 칸 위치로 세라** —
  `fps=1/1.5,scale=200:-1,tile=12x9` 면 한 칸 1.5초 · 한 줄 18초 · 한 장 162초다.

### 17-30. ★★하드섭이 완성본에 남았다 — 검출기와 `reframe` **두 군데**가 틀렸다 (2026-09-13)

사용자: *"증거를남기지마라에서 조금만 화면을 크게 하면 원작의 글자가 안 보일 거 같은데"*
완성본을 보니 원작 자막의 **윗줄**이 그림 아래에 그대로 남아 있었다. 원인이 두 개였다.

**① `prep.py` 의 검출기가 33px 낮게 잡았다.**
200장의 **흰 픽셀 비율을 평균**내어 문턱(2%)을 넘는 첫 행을 띠로 삼았다.
그런데 자막이 **두 줄일 때만** 쓰이는 윗줄은 전체 프레임의 몇 %에만 나온다 —
평균을 내면 그 행이 문턱 아래로 깔린다. 그래서 **아랫줄 위쪽**을 띠로 잡았다.

| | 검출값 | 실제 |
|---|---|---|
| 경성크리처 1화 | y931 | **y905** (두 줄일 때) · y981 (한 줄일 때) |

→ **프레임마다 "자막처럼 보이는 행"을 세고, 200장 중 8장에만 나와도 띠로 인정한다.**
  흰 픽셀만 세면 밝은 화면을 자막으로 오인하므로 **흰 글자(≥240) 옆 ±7px 에 검은 테두리(≤50)**
  가 있는 행만 센다(§17-10 과 같은 잣대). 고친 뒤 같은 소재에서 **897** 이 나왔다.

**② `reframe.py` 가 크롭 아래끝을 소재 전체 높이로 막고 있었다.**
`py = min(max(py, h/2), SH - h/2)` — `SH` 는 1080 이다.
화자를 따라 크롭이 내려가면 `crop_filter` 가 애써 잘라낸 자막이 **그 구간만 도로 살아난다.**
g26 에서 세 구간이 침범했다 — 18.4초(아래끝 987) · 22.4초(941) · 178.8초(978).
**22.4~23.4 구간은 마침 23.0초에 자막이 뜨는 자리였다.**

→ `_YMAX = HARDSUB_TOP or SH` 를 두고 `py` 를 **그 선 위로** 막는다.
  `w ≤ CW0` 이므로 `h ≤ CH0 ≤ HARDSUB_TOP` 이라 항상 답이 있다.

**★고치고 나서 확인하는 법 — 눈으로 보지 말고 재라.**
그림 맨 아래 띠(우리 자막이 닿지 않는 곳)를 **전 프레임** 훑어 글자 같은 픽셀을 센다.

```
# 1080x1920 완성본에서 y1375~1466 을 본다 (그림은 y453~1467)
ffmpeg -v error -i <완성본> -f rawvideo -pix_fmt gray - | (흰≥240 AND ±7px 안에 어두움≤50) 세기
```
g26 은 **1185장 전부 0장**, 최대 17픽셀(잡음)로 통과했다.

★**덤으로 화면이 커진다.** 띠를 931→897 로 내리면 크롭이 990x930 → **954x896** 으로 좁아진다.
  세로로 세울 때 같은 1080 폭으로 늘리므로 **그림이 3.7% 더 크게** 나온다.
  사용자가 "화면을 조금만 크게 하면"이라고 한 게 정확히 이것이다.

★**이미 구운 편을 의심해라.** 하드섭이 있는 소재로 만든 편은 같은 병을 앓고 있을 수 있다.

### 17-40. ★말하는 사람은 **목소리 높이(F0)** 로 가른다 — 샷만 믿지 마라 (2026-09-15 · 7화)

(16kHz 모노 · 70~1000Hz 대역 · 40ms 창 · 20ms hop).

| | 장태상 | 인혁 | 채옥 | 나월댁 |
|---|---|---|---|---|
| F0 중앙 | 92~121Hz | 132~165Hz | 188~323Hz | 150~276Hz (흔들림) |

### 17-44. ★세로 쇼츠(1080x1920)가 소재일 때 — 그림 칸만 오리고 ZOOM 을 덮어쓴다 (2026-09-15 · mk01)

1. **그림 칸의 행 범위를 재서 그 칸만 오린다.** 검은 행(비율 50% 미만)의 연속 구간을 세면 나온다 —

### 17-45. mk01 에서 새로 생긴 손잡이 세 개 — 효과음 자리 · 배경음악 빼기 · 커스텀 보이스 (2026-09-15)

**① 특정 자리의 휙 효과음을 빼거나 바꾼다 — `SFX_RULES`.** 사용자: "너 부산 다시 내려갈래? 여기 대사에서 나오는 효과음 변경 가능할까?"
```python
SFX_RULES = [(("D", 5), None),                 # 5번째 대사 블록 시작 자리(±0.5초)의 whoosh 를 뺀다
             (("N", 2), "sfx/boom.wav", -12)]  # 2번째 나레 마디 시작에 다른 파일을 깐다 (셋째 = dB)
```
앵커는 효과자막과 같은 꼴(블록 번호)이라 나레 길이가 바뀌어도 자리가 안 밀린다. `build.py` 가 "효과음 38.7s 자리 뺌" 으로 찍어 준다.

**② 대사 구간 배경음악 빼기 — demucs.** 사용자: "너 부산 다시 내려갈래 할 때 배경음악을 좀 지워 줘" → 이어서 "똑바로 하자"까지.
이 PC 의 시스템 파이썬(`python`, 3.11)에 demucs 4.1 + torch(CPU)가 있다. venv 가 아니다.
```
ffmpeg -i src_orig.mp4 -vn -ac 2 -ar 44100 _src_audio.wav
python -m demucs --two-stems=vocals -n htdemucs -o _sep _src_audio.wav      # 57초에 30초쯤 걸린다
```
`_sep/htdemucs/_src_audio/vocals.wav` 를 원음과 섞되 **구간 가중치 g(t)** 로 넘긴다(앞뒤 0.1초 램프):
```
[0:a]volume='1-G':eval=frame[o]; [1:a]volume='G':eval=frame[v]; [o][v]amix=normalize=0
G = max(0,min(1,(t-45.62)/0.1))*max(0,min(1,(55.30-t)/0.1))
```
그 결과 위에 §17-44 의 편집자 나레 mute 를 다시 건다(순서 주의 — `src_orig.mp4` 에서 매번 새로 만든다).

**③ 커스텀 보이스는 API 키 계정에 있어야 한다.** 스튜디오에서 만든 "드라마"는 `/v1/voices`·`/v1/custom-voices` 어디에도 안 떴다
(계정이 다르다). 사용자가 준 샘플로 **즉시 클로닝**해서 이 키에 만들었다:
```
POST https://api.typecast.ai/v1/custom-voices/instant-clone   (multipart: file=wav, model=ssfm-v30, name=드라마)
→ {"voice_id":"uc_6aa8eb42d1b77888a4240797","status":"completed"}
```
필드 이름은 `name` 이다(`voice_name` 은 422). 샘플은 말이 있는 구간만 잘라(21초) loudnorm -18 로 넣었다.

★`tts.py` 의 캐시 도장에 **목소리·배속**을 넣었다 — 전에는 문구만 봐서 보이스를 바꿔도 옛 목소리가 남았다(§17-25 와 같은 병).

### 17-47. ★박힌 글자는 Vmake 로 지우고 그림 칸 **전체**를 쓴다 (2026-09-15 · mk01 vmake 판)

사용자: "vmake로 텍스트 모두 지우고 만들어줘". §17-44 의 "그림 칸만 오린다"는 반쪽이었다 —

   ```
       run-task --task SKM0002 --input "<절대경로>/src_pic.mp4" --agent-name claude-code > vmake_result.json 2> vmake_stderr.log
   ```
