## B. 소재 고르기

1. **★조회수를 가른 건 편집이 아니라 소재다.** 분노·희생·역사가 걸린 장면(마루타·생체실험·학살)은 조회 중앙 10.7만,
   줄거리를 진행시키는 인물 장면은 3.4만 — 같은 작품 안에서 30배 차이가 났다. **줄거리 진행 장면은 고르지 마라.** (§17-26)
2. **한 작품을 순서대로 연재한다.** 소재를 이것저것 섞지 않는다. (§17-26)
3. **벤치는 고정된 게 아니다.** 편을 만들기 전에 벤치 채널을 다시 재라. (§17-26)
4. **소재의 샷 수를 대사보다 먼저 센다.** `prep.py` 의 전환 검출은 어두운 방·느린 컷을 놓친다(“전환 0곳” → 실제 12곳).
   축소 96x54 흑백 · 평균차 9 로 직접 잰다. 45초에 샷 두세 개면 버린다. (§17-33)
5. **단일 롱테이크는 버리지 말고 `CROP_SHOT` 으로 컷을 만든다** — 클로즈(왼)·클로즈(오)·투샷을 번갈아.
   손으로 다 지정했으면 `reframe.py` 를 돌리지 마라. `build.py` 의 `crop_at` 은 y 를 1080 으로 클램프하므로
   `중심y + h2/2 ≤ HARDSUB_TOP` 인지 손으로 확인한다. 말하는 사람을 얼굴 상자 움직임으로 자동 판정하지 마라. (§17-34)
6. **자르고 나면 0초·중간·끝 프레임을 한 장씩 뽑아 본다.** 타이틀 카드(검은 화면+로고)에 목소리만 깔린 구간이 있다. (§17-36)
7. **펀치 대사 뒤로 그림이 10초 이상 남게 구간을 잡는다.** 닫는 나레 두 마디는 마지막 대사 이후의 그림만 쓸 수 있다. (§17-37)
8. **소재 파일의 출처를 재서 확인한다.** 이름만 바꾼 불법 스트리밍 재인코딩 파일이 있었다 — 길이를 0.01초까지,
   같은 시각 프레임을 대조한다. (§17-43)
9. 전편 전사가 이미 있으면 **구간별로 오려 쓴다** (시각은 구간 시작 기준으로 다시). 5초 넘는 침묵으로 묶으면 사건 지도가 된다. (§17-38)

- 인물은 **반드시 이름으로** 부른다. (§17-26)

## D. 나레이션

1. **나레는 대사를 따라 하지 않는다 — 이야기를 몰아간다.** 대사가 말하지 않는 것만 말한다(때·곳·관계·이름·앞뒤 사정·결과).
   `build.py` 가 앞뒤 대사와 2글자 겹침 34% 이상이면 막는다. (§17-20)
   예) "건물을 무너뜨리지는 못한다고 했습니다"(되풀이) → **"혼자 들어가 옹성병원을 무너뜨릴 셈이었습니다"**
2. **나레는 이름, 자막은 들리는 대로.** 사람들이 부르는 말이 직함(「장 대주」)이면 자막은 직함 그대로.
   하오체(~소/~오/~요)를 반말(~야/~어)로 떨어뜨리지 마라. (§17-24)
3. **이름이 대사로 나오기 전에는 앞질러 부르지 않는다.** 하드섭 화자 표시로 알게 된 호칭(「최 군」)만 쓴다. (§17-40)
4. **숫자+단위 규칙은 수량사에도 걸린다** — "상자 몇 / 개뿐" 으로 갈리면 문구를 고친다("상자 몇 개가 전부였습니다"). (§17-29)
5. 그림을 못 바꾸면 **문구를 그림에 맞춘다** — 트럭이 떠나는 그림이 없으면 "트럭이 떠나는데"라고 쓰지 마라. (§17-41)

## E. 싱크 — 엔진에 박힌 것과 내가 확인할 것

1. **프레임 격자** — `build.py` 가 모든 길이를 1/FPS 에 맞추고 컷마다 프레임 수로 못 박는다(±0.24초 → ±0.02초).
   필터는 `_fc1.txt`·`_fc2.txt` 에 쓰고 `-/filter_complex <파일>` 로 넘긴다. **이 고침 전에 구운 편은 다시 구워야 한다.** (§17-21)
2. **캐시는 입력이 바뀌면 깨야 한다.** `align.py` 는 나레 원문+wav 도장(`narr/_all.asr.stamp`), `tts.py` 는 `narr/n{i}.txt`
   로 문구가 바뀌면 다시 만든다. "파일이 있으면 건너뛴다"는 단계마다 의심해라. (§17-23 · §17-25)
3. **사용자가 같은 말을 세 번 하면 내 측정 자리가 틀린 것이다.** `synccheck.py` 는 대사 블록을 잰다 —
   **나레 자막 덩이**는 완성본에서 덩이 한가운데 프레임을 떠서 **글자를 눈으로** 확인한다. (§17-23)
4. **흐린 말을 앞 자막으로 덮는 건 1초까지.** 3.2초 넘게 떠 있는 대사 자막은 `build.py` 가 막는다.
   말 사이 침묵이면 **자막을 둘로 쪼개고**, 흐린 말이면 **그 자리를 블록에서 뺀다.** (§17-20)
5. 블록을 못 나누는 자리(말 사이 0.34초 미만)는 한 블록에 담는다. 말 사이가 0.5초를 넘으면 쪼개 **맞붙여** 죽은 구간을 없앤다.
   0.34 < 사이 ≤ 0.5 는 그냥 둔다. (§17-35)

## F. 전사 — 시각은 믿고 글자는 화면에서

1. 기본: `python scripts/_asr_sm.py <src.mp4> <asr.json> ko` (Speechmatics · 키 `~/.volcano/keys/speechmatics`)
2. **대사가 일본어인 구간은 `ja` 로 전사해 시각만 쓰고, 글자는 화면 하드섭(공식 한국어 자막)에서 읽는다.**
   하드섭 띠만 오려 쌓아 보면 빠르다: `ffmpeg -ss <t> -i src.mp4 -frames:v 1 -vf "crop=1920:160:0:920" f.png` (§17-28)
3. **한국어·일본어가 섞인 장면은 전사를 두 번** 돌려 각 언어 구간의 시각을 따로 쓴다. `dlgcheck` 도 두 번 돌리고,
   어긋나면 **그 구간 언어 쪽**을 믿는다. 그래도 헷갈리면 **소리로 판정** —
   `ffmpeg -nostdin -hide_banner -ss <t> -t <d> -i src.mp4 -af volumedetect -f null -` (★`-v error` 를 주면 결과가 지워진다) (§17-31)
4. **시대극·사극은 두 번째 귀를 댄다** — Gemini(`~/.volcano/keys/gemini`)로 통째로 다시 받아 적고 다수결(3:0·2:1 만 고친다).
   종결어미(하오체/반말)와 호칭(이름/직함)을 특히 본다. (§17-24)
5. **사투리·어설픈 발음은 전사가 거의 다 틀린다**(열두 줄 중 아홉). 시각만 쓰고 글자는 하드섭. (§17-38)
6. **전사가 웅성거림을 낱말로 지어내기도 한다.** 하드섭이 없는 구간은 대사로 쓰지 마라. (SESSION-LOG 09-14)
7. 키가 죽으면(401): `python presets/포레이로/cuescan.py <편폴더> [0.1] --json` — 하드섭이 뜨고 지는 시각으로
   `cues_asr.json` 을 만들어 `dlgcheck` 를 돌린다. 낱말 시각을 대신하지는 못하니 **막혔을 때만.** (§17-32)
8. 긴 소재 전사 중 502 가 나면 **다시 올리지 마라(돈이 두 번 나간다).**
   `python scripts/_asr_sm_fetch.py <job_id> <출력.json>` 으로 결과만 받는다. (§17-39)

## J. 효과자막

- 앵커는 **블록 안쪽** `(("C", n, k, 0.05), "글자", "right")` — n번째 대사 블록의 k번째 자막이 끝나고 0.05초 뒤.

## L. 돌리는 요령·함정

- **동시에 굽는 것은 세 개까지.** 네 개면 ffmpeg 이 메모리 부족(exit -12)으로 죽는다. (§17-38)
- 셸에서 변수 대입을 백그라운드 목록에 묶지 마라(`V=... && ffmpeg ... &`) — 다음 명령에서 변수가 빈다. 대입은 따로 줄에. (SESSION-LOG 09-15)
- **한글이 든 경로의 onnx 는 윈도 OpenCV 가 못 읽는다** — `reframe.py` 가 ASCII 경로(`%TEMP%` 또는 `C:/vol_models`)로 복사해 쓴다.
- yt-dlp 는 **pip 판**을 쓴다(winget 판은 403). 채널 긁을 때 `--sleep-requests 2`.
- 타입캐스트 402 = **API 크레딧 잔액** 문제다(스튜디오 크레딧과 별개). typecast.ai/developers/api 에서 확인.

## M. ★나레 말투 확정 — 「알파카 말투」 (2026-09-18 · 사용자 확정, mk07b 1차 기준)

사용자가 카톡으로 준 벤치 6편(`docs/벤치-알파카채널-나레분석-20260918.md`)을 분석해 mk07b 로 샘플을 굽고 **"이 말투로 확정"** 했다. 다음 편부터 기본이다.
mk02 때 박은 「~하는 [인물]」 명사구 문체(claude-memory/forey-rules.md 09-15)는 이걸로 **대체**한다.

1. **나레 = 3인칭 · 과거 · 존댓말 한 문장, 10~18자, 한 마디 한 정보.** 문어체 "~다/~습니다" 금지.
2. **어미는 두 가지** — `~죠/~었죠/~는 거죠`(마디를 맺을 때) · `~는데/~건데`(다음 대사로 넘길 때).
   ★`~기에`는 **쓰지 않는다**(사용자 2026-09-18 "기에라는 말투를 안 썼으면"). 물음표 「~데?」·`|` 덩이 나누기도 빼라고 했다(2·3차 시도 → 1차로 복원).
3. **인물은 이름·자신·그·그녀·관계어(형·동생·오빠·누나)** 로 부른다. ★**나레에서 직함·신분은 말하지 않는다**(백 부장·백 중령·오 검사·장 고문·육사 생도 ✗ — 사용자 2026-09-18). 대사 자막의 직함은 들리는 대로 둔다.
4. **나레는 대사를 되풀이하지 않는다** — 이유·심리·결과만. "너무나도 달콤했죠", "딱 봐도 감시할 목적으로 쥐새끼를 심은 건데". `build.py` 겹침 검사(§19)에 걸리면 낱말을 바꾼다.
5. **샌드위치**: 나레(주어·상황) → 대사 → 나레(평가). 나레 두 마디가 연달아 오면 사이에 대사를 끼울 수 있는지 먼저 본다.
